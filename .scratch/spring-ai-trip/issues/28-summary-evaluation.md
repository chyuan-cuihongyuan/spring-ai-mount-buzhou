# 摘要质量评测方案

Type: grilling
Status: resolved
Blocked by: —

## Question

九段式摘要模板（ticket 09 已定稿）如何验证质量：评测指标怎么定（意图保留率、任务续接成功率、关键事实召回、token 压缩率）？评测数据集从哪来（构造多轮基准会话脚本？录放真实会话？）？评测在 Spec 里写到什么程度（只给方法论，还是连评测工具/脚本的设计也给）？微压缩 + 摘要的两级联动怎么测（端到端：20 轮会话后 P0 信息仍在）？这项设计进 Spec 的哪份文档？

## Answer

**定案：四指标 + 脚本数据集 + Spec 写方法论 + 端到端用例入 01 文档。**

1. **指标**：P0 信息保留率（意图/现场/下一步逐条核对）、任务续接成功率（压缩后续跑，LLM-as-judge 评分）、关键事实召回率（预埋事实探针）、token 压缩率（纯统计）；前三者 judge + 人工抽检校准。
2. **数据集**：构造基准会话脚本集（预埋意图/事实/转折的多轮脚本，覆盖排障/编码/数据分析三场景），入 examples 模块；Spec 只写方法论——指标定义、判官 prompt 模板、跑法；评测工具实现归工程期。
3. **两级联动**：端到端用例——20+ 轮混合大小工具返回会话，跑完断言 P0 仍在、evidence 指针可回查、预算曲线无越限；写入 `docs/spec/01-memory-compaction.md` 评测专节 + examples 可跑脚本设计。

### 影响面

- 雾「性能基准与压测方案」部分毕业：压缩质量的验收标准已定；纯性能项（并发吞吐/延迟）仍留雾中，待机制实现期成形。
