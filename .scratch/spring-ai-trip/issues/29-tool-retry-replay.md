# 工具中断重试与重放策略

Type: grilling
Status: resolved
Blocked by: —

## Question

续接加载发现未完成 tool_call 时的重试/重放细则（ticket 10 定案的入口：先重试，重试全部失败后才进入悬空修复）：重试触发条件（哪些中断值得重放、哪些直接判悬空）？重试次数与退避策略？幂等边界——有副作用的工具重放是否安全，是否需要工具声明幂等性元数据？与 HITL 危险工具守卫（ticket 25）如何交互——危险工具重放是否需重新授权？重试过程本身是否记入 Span/Event？

## Answer

**定案：幂等白名单重放 + 续接重放一次 + 危险工具重新授权 + span 因果串联。**

1. **幂等边界**：工具声明幂等性元数据（`@BuzhouTool(idempotent=true)` 或策略配置）；**仅幂等工具自动重放**，未声明/非幂等直接判悬空走 10 的修复——「能重试」是白名单而非默认。
2. **次数与退避**：续接重放只一次（中断重试 ≠ 运行时重试，避免反复撞同一故障）；运行期瞬断重试独立可配：默认 0 次，指数退避 1s/2s/4s 上限 3 次；两者分开配置互不混淆。
3. **HITL 交互**：危险工具重放必须重新授权——25 的一次性授权语义自然覆盖（长效授权除外）；重放请求走同一守卫通道，无特例。
4. **可观测**：重试/重放产生 HarnessInternal span（尝试次数、退避、成败）；最终失败转悬空修复时与 10 的修复 Event 因果关联（父 span 串联），排障可追「重放了几次、为什么放弃」。
