# PII 脱敏与数据加密

Type: grilling
Status: resolved

## Question

> **12 已决(2026-08-11)**:护栏执行平面与三动作(阻断/遮蔽/仅标记放行)已确立,挂 beforeModel/afterModel——PII 脱敏的执行位与"遮蔽"动作与该平面同炉;本票专注 PII 特有问题:识别器、可逆映射、**存储形态**(持久化层存原文还是脱敏后)。LangChain PIIMiddleware 是主要蓝本。

框架是否提供**数据脱敏与加密**?(参考文档七.2:自动识别手机号/身份证/银行卡,入参脱敏、日志脱敏;七.5:会话数据加密存储、敏感上下文禁止打印日志)

需回答:
1. **做不做**——PII 进模型前脱敏、日志脱敏、存储加密是框架职责还是用户业务
2. **机制边界**——脱敏 vs 假名化(可逆映射,模型需要语义一致性时可逆)的选择;**脱敏作用域的关键取舍**:只脱入模流量,还是持久化层也存脱敏后版本(存原文则证据链完整但泄露面大,存脱敏则回放/审计看不到原文)
3. **接缝**——与 MessageStore(存什么形态)的关系;与记忆压缩/九段摘要的穿透(摘要会不会带出 PII);与 Spill 落盘(明文文件)的关系;与 observability 事件(思维链事件含 PII?)的关系

答题要求:同 08 号票(做/不做 + 机制边界 + 接缝;借鉴成熟实现并注明来源)。

## Answer

(2026-08-11,grilling 收口,三问全采纳推荐)

**决策:做**——入模脱敏 + 日志事件脱敏 + 存储加密装饰器;双模脱敏;存储形态显式双档。

**机制边界(管什么/不管什么)**:
- **入模脱敏**:护栏平面同炉(12 已立)——识别器 SPI + 内置正则识别器(手机号/身份证/银行卡等),动作复用三动作(阻断/遮蔽/仅标记)
- **日志/观测事件脱敏**:同一识别器复用,观测管线加脱敏环节(思维链事件是泄露重灾区)
- **存储加密**:装饰器式 SPI 包装(借 OpenAI EncryptedSession 蓝本);**密钥管理归用户**(KMS),框架不管密钥——与 12"做执行平面不做检测器"同一哲学
- **双模脱敏**:`redact`(默认,简单安全)+ **假名化**(可逆映射——`PHONE_1` 式占位,会话内映射表保持一致使模型语义不断裂;映射表随会话生命周期销毁,存储细则留 Spec)
- **存储形态显式双档**:默认"入模脱敏+持久化存原文"(证据链完整——evidence-id 回查/回放/审计见原文,泄露面靠加密装饰器+部署侧访问控制收敛);高合规档"全链路脱敏"(存脱敏版,明示代价:回放/审计所见即脱敏)
- **不管**:密钥管理、算法选型(部署方);识别器的高精度 ML 模型(内置正则,重型识别接外部服务)

**接缝**:
- 穿透点联动(留 Spec 细化):摘要引擎走模型调用→经同一护栏平面,摘要天然继承脱敏;spill 落盘与观测事件流随档位联动(原文档=spill 原文+加密,脱敏档=全脱敏)
- 与 22 数据生命周期的删除彻底性协同(脱敏档下删除面更小)
- 策略走 policy 四层配置;事件进 observability

**借鉴**:
- LangChain PIIMiddleware(检测器可插/动作可配/作用点可选)— https://docs.langchain.com/oss/python/releases/langchain-v1
- OpenAI Agents SDK EncryptedSession(加密=存储装饰器)— https://github.com/openai/openai-agents-python
- Microsoft Presidio(假名化/可逆映射的业界成熟做法)— https://microsoft.github.io/presidio/
