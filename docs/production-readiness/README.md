# 生产就绪缺口盘点与取舍路线图

> 不周山 wayfinder「production-readiness」地图的 Destination 产物（2026-08-11 收口）。
> 问题：**让单个业务 Agent 稳定、可控、可解释地跑在生产里，还需要补全哪些功能？**
> 过程档案（22 张决策票全文）：`.scratch/production-readiness/`；借鉴与引用清单：[references.md](references.md)。

## 方法与口径

- **参照系**：通用企业生产（toB 私有化 + 企业内部助手）；单 Agent 边界（多 Agent 编排、多模态、模型选型出图）
- **排序权重**：稳定 > 可控 > 可解释
- **决策方法论**：能借鉴成熟开源项目（LangChain/LangGraph 等业内认同度高的）的治理实现就借鉴，不重新发明；无现成借鉴时须有博客/研究支撑；纯自主推演标注 `> 【推演】`
- **决策统计**（22 票）：做 11 · 部分做 9 · 基本不做 1（实例生命周期）· 不做 1（RAG 治理）

## 横向主题：五家族

22 张票的答案收敛为五个横向家族，作为 Spec 阶段的组织单位：

1. **韧性家族**（03/04/09）——故障应对：模型韧性（重试/熔断/超时/错误归一化）→ 模型路由（降级链/档位组）→ 工具容错（重试/清洗/兜底/熔断/缓存）。同一状态机概念贯穿模型级与工具级。
2. **失控防护家族**（07/08/11）——量级闸门：瞬时速率（限流三维）→ 行为失控（步数/重复检测/软退出）→ 累计成本（计量/预算/三级动作）。三者共享「双窗口计数 + 软信号 Attachment 注入 + 硬顶阻断转人工」的机制形态。
3. **护栏平面**（12/13/14/16）——统一挂载点（Hook 链）+ 统一动作语义（block/redact/flag-only）+ 统一治理事件（actor/action/target/outcome 四元组喂审计）；内容安全、PII 脱敏、工具权限是同一平面上的三类检测器/判定器。
4. **干预与生命周期**（05/06/15/21/22）——会话状态管理：崩溃恢复、优雅停机、运行时干预（挂起-回填原语贯通 HITL 与长任务）、租户维度、数据生命周期；全部建立在「五 SPI + 租约 + 消息即检查点」的底座上。
5. **质量与演进**（17/18/19/20/23）——可解释与演进：计划自报、回放分叉、评估沙箱、指标基线、制品版本；共同兑现「可解释」——注入快照（每轮「模型实际所见」落库）是这个家族的数据基石。

## 里程碑与依赖

```
M1 稳定基线 ──────────────► M2 可控治理 ──────────────► M3 可解释与运营
03(M1) 05 06 07 08         03(M2)+04 → 11 → 15          17 18 19 20 22 23
                            09(熔断借 03 状态机)   12/13/14 → 16(治理事件供给)
                                                   21(配额依赖 11 管线)
```

- **M1 内部**：03 M1（错误分类+重试+超时）先行，05/06 依赖恢复语义与 SPI 现状梳理，07/08 可并行；08 的「转人工」出口在 M2 15 落地前先记事件。
- **M2 内部**：03 M2 熔断与 04 降级链同炉 → 11 的三级动作依赖 04 降级链 → 12/13/14 护栏平面三件套可并行 → 15 干预平面依赖 Hook 链与脊柱取消传播（M1 已具）→ 16 审计依赖 12/13/14/15 的治理事件供给，殿后 → 21 租户维度依赖 11 预算管线（配额实例化）。
- **M3 内部**：18 fork 先行（19 的镜像替代、23 的版本对照评测都以它为执行通道）；20 指标补缺随各机制落地同步补齐（治理动作计数依赖 M1/M2 机制存在）；17/22/23 相对独立。

## 落地纪律

- 改机制先改 Spec（仓库既有约定）；本路线图是 Spec 立项的输入，不替代 Spec
- 每机制模块独立可用、feature 模块互不依赖（星形依赖白名单不变）；新模块（resilience/cost/eval）同样遵守
- 行为变更必须带测试；store 语义扩展（05/21/22）走契约测试模式
- 公共 API 变更在 PR 描述中说明兼容性影响
