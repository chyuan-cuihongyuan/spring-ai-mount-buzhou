# Spec 1897 — 多类型载荷预算分账（effort #1897，R98）

> wayfinder map：`.wayfinder/maps/effort-1800.md`（T2995–T2996，impl 1498）。借鉴：
> HTTP/2 流量控制与音频水填（water-filling）算法——总预算按权重
> 分配，需求小于份额的类型只取所需、余量回流给未满足者迭代分摊
> ——「能者多劳、按需取用」的确定性分账。

## Problem Statement

多模态消息（文本+图像+工具 schema）共享上下文/载荷预算时拍脑袋：
按类型上限硬切浪费、按需全给又爆总预算——加权水填分配（需求小于
份额取需求、余量迭代回流）缺独立计算面。

## Solution

`PayloadBudgetSplit`（core/prompt，静态纯函数 + 嵌套 Allocation）：

- `allocate(budgetBytes, demands[], weights[])`：加权水填——每轮给
  未满足类型公平份额（剩余/类型数），需求 ≤ 份额者取需求并退出，
  余量迭代回流给未满足者；返回逐类授予 + 零头（整数除法余量，
  诚实保留）；
- 分账确定性：并列需求按下标序退出。

## User Stories

1. 作为多模态组装者，预算 100B、需求 {30,50,70}、等权 → {30,35,35}
   ——小需求完整、大需求均摊、零头可见。
2. 作为权重调参者，图像权 3 文本权 1 → 图像拿大头——权重语义
   直接映射。
3. 作为预算宽松者，总需求 ≤ 预算 → 全额授予零浪费。

## Implementation Decisions

- 纯函数零状态；整数迭代水填（公平份额向下取整，余量轮末披露）；
  budget ≥ 0、demand ≥ 0、weight ≥ 1、同长 fail-fast。

## Testing Decisions

- 经典 {30,50,70}/100 等权 → {30,35,35} 零头 0；宽松全额；权重
  倾斜 3:1；单类型独吞上限；畸形四型（空表/不等长/零权重/负需求）
  fail-fast。

## Out of Scope

- 不做真实字节数量（序列化归 media 面）；不做动态重协商。

## Further Notes

- 与批级回喂预算（M-1500 系贪心截大者）互补：那是截断策略，这是
  多类型分配策略；与工具结果限幅互补：那是单流上限，这是多流分账。
