# Spec 6028 — MLFQ 多级反馈队列（effort #6028，T29）

> wayfinder map：`.wayfinder/maps/effort-6000.md`（T6257–T6258，impl 2229）。
> 借鉴：OS 调度经典 MLFQ 思想。源码于 T24 核账批预入档。

## Problem Statement

混合负载调度的病：交互任务被 CPU 密集任务压死（无优先级
区分）与固定优先级饿死低级（无行为反馈）——**多级反馈
降级面**缺失。

## Solution

`Mlfq`（core/concurrent，源码已预载）：

- levelCount 级队列、0 级最高；新任务进 0 级队尾；量子随
  级翻倍（baseQuantum<<level）；量子用满未完成降一级沉底；
  同级 FIFO；协作式单运行槽（dispatch → onQuantumExpired/
  onCompleted 二选一回报告）；
- 读数：activeTasks/readyAt(level)；fail-fast：级数/量子
  越域、重复提交、错误回报告、无运行错误回报告。

## User Stories

1. 作为调度作者，交互请求恒先于批处理——响应性底座。
2. 作为审计作者，readyAt 逐级显形——队列分布可观测。

## Testing Decisions

- 长任务逐级沉底+量子 2→4→8 翻倍+底级不降；新任务插队
  最高级；同级 FIFO；完成移出 activeTasks；双提交/错误
  回报告/级越界 fail-fast。

## Out of Scope

- 不做抢占（协作式定构）；不做时间注入（回报告即事件）。

## Further Notes

- 与 EdfScheduler（concurrent）同族不同面：截止时间优先
  vs 行为反馈降级；与 AgingPriorityQueue（exec）不同面：
  时间片老化 vs 优先级老化。
- 里程碑：T29/50（58%）。
